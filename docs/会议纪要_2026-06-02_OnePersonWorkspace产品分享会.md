# OnePerson Workspace 产品分享会 - 会议纪要

**日期**：2026年6月2日
**主讲人**：刘振华（发起人）、刘丹丹（产品负责人）、邓华（技术负责人）

---

## 📋 会议总结

> **整体节奏策略**：先聚焦员工端打磨 → 业务端快速验证 → 用户端战略性后移

---

### 🎯 核心定位

**"一个人的AI工作空间"** — 分为两个方向：

| | B2C（个人场景） | B2B（企业场景） |
|---|---|---|
| **定位** | 每个人拥有个性化的AI工作空间 | 企业专属AI工作空间 |
| **核心** | 承载个人的工作流、知识库、数据 | 对接现有系统，承载业务逻辑和知识库 |
| **目标** | 根据个人需求提供定制化服务 | 支持整个组织的协同工作 |

---

### 🏗️ 产品三大端

#### 1️⃣ 员工端（AI工作台）— MVP已出 ✅
- **面向人群**：企业内部员工
- **核心目标**：通过AI提升工作效率
- **已实现功能**：智能问答（基于知识库）、知识管理（上传/管理知识库）、个人工作台（日程管理、待办事项）
- **当前状态**：MVP版本，正在找早期用户验证
- **近期重点**：优化完善MVP

#### 2️⃣ 业务支持端（AI服务平台）— 规划中 🏗️
- **面向人群**：销售、客户成功、市场等业务团队
- **核心目标**：用AI赋能业务团队，让业务开展更高效
- **计划模块**：**客户管理**、**商机管理**（老板重点关注）、数据分析和洞察
- **当前状态**：已完成销售/客户成功团队访谈调研，正在梳理需求
- **近期重点**：尽快做出原型验证假设

#### 3️⃣ 用户端（AI应用）— 未开始 🔜
- **面向人群**：最终用户（C端）
- **探索方向**：AI原生笔记工具、AI Agent平台
- **当前状态**：前期市场调研阶段
- **节奏建议**：稍后推进，等员工端和业务端积累更多认知后再深入

---

### 🧱 技术架构（邓华分享）

**设计原则**：模块化、可扩展、开放性（API+插件机制）
**部署环境**：阿里云（云原生技术栈）

**四层架构：**
| 层级 | 内容 | 技术栈 |
|------|------|--------|
| ① 接入层 | API网关 + 客户端SDK | Web端、移动端SDK |
| ② 业务应用层 | 员工端 / 业务支持端 / 用户端 | 具体的业务逻辑和用户体验 |
| ③ **AI能力层**（核心） | 大模型推理 + RAG引擎 + Agent框架 | GPT/Claude/文心一言 |
| ④ 基础设施层 | 容器编排 + 存储 + 消息队列 | Kubernetes + 对象存储 |

**技术规划方向：**
- 优化大模型推理效率和成本
- 完善Agent框架，支持复杂任务编排
- 探索多模态理解、代码生成等新能力

---

### 🎯 老板（振华）核心关切

1. **分层分场景的体系**：产品不是单一工具，而是员工内部提效、业务外部赋能、用户最终触达，三者缺一不可
2. **员工端**：当前核心，先跑通MVP、获取用户反馈，快速迭代验证
3. **业务支持端**：**老板非常重视！** 这是直接产出商业价值的端（销售/客户成功），需要尽快出原型验证
4. **用户端**：虽然目前后置，但这是B2C的长期方向，需要持续积累认知
